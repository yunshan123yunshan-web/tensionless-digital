# Decision Rules

When choosing between speed and quality:

- Default: quality first. Speed is secondary unless explicitly stated.

When choosing simple vs flexible:

- Prefer simple. We can add complexity later. We can't remove it easily.

When choosing build vs buy:

- Build if it's core to our product. Buy if it's a commodity capability.

When prioritizing features:

- Impact over effort. Use a simple 2×2 matrix, not weighted scoring.

When giving feedback:

- Be direct but kind. No sandwich technique. Say what needs to change.

When to use:

  • Technical architecture choices
  • Strategy & planning
  • Prioritization decisions
  • Any "it depends" scenario

Tip: Start with 5 rules. Add more as you notice Claude making choices you wouldn't have made. Each rule captures a judgment call you've already made — once.

Think of this as encoding your intuition into reproducible guidelines.
